# US154 - Run the candidate pass from Process and show candidates in Review

## What we analyzed

Process currently runs only unit knowledge extraction. Review shows knowledge results and nothing else. This item adds the candidate pass after extraction on the same selection, with its own state, so a failure in one pass does not hide the other. Candidates stay local. The design follows the earlier decision that the desktop shows results and uploads nothing new.

## Affected modules and files

All paths sit under `desktop/collector`.

- `KnowledgeRunViewModel.ExtractKnowledgeCommand` - runs the candidate pass after the unit extraction on `_documentIds`, with the same cancel command and Escape binding.
- `CandidateRunState` - new singleton, separate from `KnowledgeRunState`.
- Review screen - new Candidates panel in its own component, so US150 edits to the Process screen do not collide with it.
- Banner view - reused for the missing key, too large, key rejected, all keys failed, quota, network and canceled outcomes.
- Settings - target of the missing key banner link.

## Assumptions

- The candidate pass is chained in the existing command, not started by a second button.
- Progress shows one count per document.
- The Candidates panel shows the excerpt reference, and an unverified excerpt carries a visible mark.
