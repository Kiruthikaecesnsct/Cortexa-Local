# US128: Show Batch Progress and Candidates in History

## Scope & Prerequisites

- **Backend prerequisite folded in from proposed US129 follow-up**: Server-side extension of batch and results endpoints now part of this story. Originally planned as a separate item; folded to keep History UI and its data contracts together.
- **Collector server stays independent**: Must run on `localhost:5091` separately from main preview stack.
- **No changes to services/ or frontend/**: All code lives inside `Cortexa-dev/desktop/collector/` (both server and UI).

## Contract Extensions (Backend)

Two endpoints extended via this story's backend tasks:

### GET /collector/batches
- **Previous return**: batch list with batch_id, batch_name, created_at, raw saga state (only InProgress shown)
- **New return**: adds `stage` field (Ingested|Extracted|Scored|Harvested|Seeded) and counts for harvesting/seeding completion
- **Owner-scoping**: Returns only the caller's batches (owner + org filter applied by server; 404 never returned here)

### GET /collector/batches/{id}/results
- **Previous return**: list of knowledge links only (BatchResultDto: engine, knowledge_item {id, kind, title, summary}, source)
- **New return**: single response object `{batch_id, candidates[]}` where each candidate carries:
  - `candidate_id`, `engine`, `title`, `kind`, `evidence_count`, `score`, `patentability`
  - `knowledge_links[]` (original knowledge item + source + document_id) nested inside each candidate
- **Evidence count**: sum of `ARRAY_LENGTH(hits)` across all `evidence_bundles` rows for that candidate_id
- **Score & patentability**: score = `verdict.composite_score`; patentability = `verdict.axes.Patentability.score` (0-100). Fallback: if no verdict, use `report.weighted_score` / `report.axes.Patentability`; if neither, null.
- **Document ID**: Each knowledge link carries `document_id` from the chunk row; client computes server document IDs via `DeterministicIds.DocumentId(serverBatchId, clientDocId)` (moved to Collector.Domain); no SQLite migration needed.
- **Stage derivation**: Derived from per-document saga states—lowest rank among non-failed/cancelled documents. `Complete` or `NoCandidates` count as `Seeded` if `wants_seeding`, else `Harvested`.
- **Owner-scoping**: Returns 404 for batches owned by other users

## Affected Modules

**Backend (desktop/collector/server)**:
- `CosmosPipelineRowStore`: Add methods to query verdicts, evidence_bundles, and reports by batch_id and candidate_id; compute stage from per-document saga states
- Batch list endpoint: Return stage enum + harvesting/seeding counts; apply owner + org filter (never return 404)
- Batch results endpoint: Transform flat knowledge links + verdicts + evidence into {batch_id, candidates[]} response; include document_id per knowledge link; compute evidence_count, score, patentability per spec; return 404 for other owner's batch

**Client (desktop/collector/ui)**:
- History screen: Poll GET /batches for list view; show stage and progress
- Batch detail: Fetch GET /batches/{id}/results; render candidate cards with evidence_count, score, patentability
- Source navigation: Use DeterministicIds.DocumentId(serverBatchId, clientDocId) to compute server IDs; join to SqliteBatchStore for local file paths; enable file open on click

## Integration Points

- **US127**: Provides the initial batch polling API (GET /collector/batches); this story extends that contract
- **US126**: Prerequisite for extraction/upload; batch records created there are read by this story's polling and results endpoints
- **Local SqliteBatchStore**: Must be kept in sync with server batch writes (US126 responsibility); US128 reads it for file path resolution

- **Score & patentability source**: score = verdict.composite_score; patentability = verdict.axes.Patentability.score (0-100). Fallback to report.weighted_score / report.axes.Patentability if no verdict exists; null if neither exists. Confirmed.
- **Document ID tracking**: Knowledge links carry document_id from the chunk row. Client computes server IDs via DeterministicIds.DocumentId(serverBatchId, clientDocId), moved to Collector.Domain. No SQLite migration. Confirmed.
- **Stage derivation**: Derived from per-document saga states—lowest rank among non-failed/cancelled. Complete/NoCandidates count as Seeded if wants_seeding, else Harvested. Confirmed.
- **Response structure**: GET /collector/batches/{id}/results returns {batch_id, candidates[]} not a bare array. US127 endpoint tests updated. Confirmed.
- **Owner-scoping clarification**: GET /collector/batches only returns caller's batches (owner + org filter); 404 only for GET /collector/batches/{id}/results when another owner's batch is requested. Confirmed.
