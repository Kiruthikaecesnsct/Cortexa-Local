# US151: GitHub device flow and App sign-in

## Scope

- Adds two GitHub auth options to the desktop collector Remote source connect step: OAuth device flow and GitHub App user-to-server tokens.
- PAT stays as the fallback. Existing PAT users see no change.
- Desktop only. Talks to github.com directly. No Cortexa endpoint, so Contract is None.
- Out of scope: reuse of gh CLI or Git Credential Manager logins (already handled), SSH.

## Affected files (desktop/collector/src)

- Collector.Infrastructure/Remote/PatAuthHandler.cs and PatScheme.cs: pattern for the new auth handler and scheme selection.
- Collector.Infrastructure/Remote/RemoteSourceRegistration.cs: Authorization header already redacted here; keep it that way.
- Collector.Infrastructure/Remote/GitHub/*: existing GitHub clients get the token the same way the PAT does.
- Collector.Infrastructure/Secrets/CredentialManagerStore.cs: only token store. Sign-out clears it.
- Collector.Application/Remote/RemoteConnectRules.cs: auth-method rules.
- Collector.Presentation: RemoteSourceView, RemoteSourceViewModel (+ .Wizard, .Repositories partials).

## Assumptions

- Device flow needs no client secret. Client IDs are config-driven.
- The App refresh token rotates. Store the new pair on each refresh.
- Repo listing for the App comes from the installation grant, so the collector lists only granted repos.

## Resolved

- Token persistence (decided 2026-10-13, see `decisions/20261013-collector-oauth-token-persistence.md`): the US151 GitHub App and device flow tokens may be stored encrypted in Windows Credential Manager so sign-in survives a restart. Approved exception to US138 for OAuth tokens only. PATs and the SSH passphrase stay session-only. The US138 startup purge must skip the OAuth slots. Sign-out clears them.

## Prerequisites

- None in the backlog. The App registration and org approval are external prerequisites, not stories.
