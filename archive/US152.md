# US152: Entra ID sign-in for Azure DevOps

## Why and how

- Adds Microsoft Entra ID sign-in to the collector Remote source connect step for Azure DevOps. PAT stays as the fallback and is not changed.
- MSAL public client. WAM broker first, system browser when the broker is unavailable, device code last. Scope `499b84ac-1321-427f-aa17-267ca6975798/.default`. The old Azure DevOps OAuth app registrations are not used.
- Org URL stays required. Out of scope: service principals, Azure CLI token reuse, SSH.
- Reuse RemoteTokenAuthHandler, IRemoteTokenSource and IRemoteAuthState from US151. Add RemoteAuthMethod.EntraId and an EntraIdTokenSource. No new Bearer handler.
- Folded prerequisite (pre-flight, 2026-10-21): MSAL cache chunking. CredentialManagerStore has a 2560-byte blob limit. The MSAL cache adapter splits the cache across numbered targets, reads them joined, and deletes every chunk on sign-out. The store limit does not change.

## Affected files (desktop/collector/src)

- Collector.Infrastructure/Remote/AzureDevOps/*: client switches to RemoteTokenAuthHandler.
- Collector.Infrastructure/Remote/PatAuthHandler.cs and PatScheme.cs: untouched.
- Collector.Infrastructure/Secrets/CredentialManagerStore.cs: limit unchanged. Chunking lives in the MSAL cache adapter.
- RemoteAuthMethod, RemoteConnectRules.cs, RemoteFailureMessages: EntraId choice and Entra no-access text.
- Config: client ID, authority and redirect URI in AzureDevOpsSourceOptions.
- Presentation: RemoteSourceView.xaml is 1486 lines, so Entra UI goes in its own panel. Reuse the GitHubDeviceCodePanel layout, not DeviceFlowRunner, because MSAL polls by itself. WAM needs the WPF window handle.
- OAuthSignOutListener: also clears Azure DevOps Entra state.
- Directory.Packages.props: Microsoft.Identity.Client and Microsoft.Identity.Client.Broker at the live-checked latest stable.
- Tests: StaleRemoteSecretPurge must keep the MSAL slots.

## Assumptions

- Client ID, authority and redirect URI are config-driven. Public client, no secret shipped.
- MSAL cache bytes go only through CredentialManagerStore, never to settings or logs.

## Open questions

- Alpha confirms or creates a public-client Entra app registration: Azure DevOps user_impersonation delegated permission, redirect `ms-appx-web://microsoft.aad.brokerplugin/{clientId}`, public client flows on.
- Single-tenant or multi-tenant? Does the delegated permission need admin consent?
- Is the target org Entra-backed? If not, PAT stays the only path.
- Provides key `secret:entra-id-token-cache` is not recorded in the JSON yet (legacy story, no ledger).

## Resolved

- Token persistence (2026-10-13, `decisions/20261013-collector-oauth-token-persistence.md`): the MSAL cache may be stored encrypted in Credential Manager. Approved exception to US138 for OAuth tokens only. PATs stay session-only. The startup purge skips OAuth slots.

## Prerequisites

- Folded into US152 (cache chunking). No other story needed.
- Entra app registration, tenant choice and admin consent are external, not stories.
