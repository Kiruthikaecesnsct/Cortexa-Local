# US136: Cortexa saved repository collector

## Prerequisites / scope

- **Gateway only**: All calls go through the API gateway at http://localhost:5080. Route is /scan/{**catch-all}, GET and POST. Calls need `jobs:submit` and an `Authorization: Bearer` access JWT. Without `jobs:submit` the gateway returns 403, and the desktop shows the access-denied banner.
- **Two prefixes, no single list**: /scan/github/clones and /scan/azure-devops/clones. The picker merges both. Show only clones with `status == "stored"`.
- **List call**: GET {prefix} returns clones with `clone_id`, `provider`, `owner`, `repository`, `branch`, `status`. No file data.
- **File tree**: GET {prefix}/files?owner=&repository=&branch= returns repo-relative paths only. There is no size or sha. Run RemoteFileFilter on these paths before any download.
- **Download**: GET {prefix}/download streams the whole branch as one zip. Pre-flight fold (Task "Read Cortexa download zip safely"): download once per branch into the remote cache root, extract entries on demand with a zip-slip guard and the existing size caps, delete the temp archive when done.
- **Server reference**: services/ingestion/.../repository_clone_routes.py. Web reference: frontend/src/features/scan/cloneApi.ts. Read only, never edit.

## Contract and prerequisites

- **Contract** (`exists:gateway clone /files and /download`): already built on the server. No story needs to deliver it.
- **Desktop already has**: SourceType.CortexaRepo (serializes to `cortexa_repo`), the `remote_files` table (provider `cortexa_repo` allowed), the IRemoteRepositoryClient ports, RemoteFetchService, and BearerTokenHandler.
- **Still missing, all inside desktop/collector**: CortexaGateway named HttpClient, Cortexa repo client, zip reader, and the fifth source card and picker UI.
- **Depends on**: US126 (extraction and upload), US134 (GitHub and Azure DevOps collectors), US135 (SSH collector).

## Affected areas

- desktop/collector only. No edits to services/, contracts/, frontend/ or deploy/.
