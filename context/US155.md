# US155 - Fall back to the next Gemini model with quota when all keys hit QuotaExceeded

Analysis behind this work item. Written at creation by project-manager-expert. Keep it about 400 to 600 tokens.

## What we analyzed

Gemini is called only from the desktop collector (`desktop/collector`). `GeminiDirectProvider.CompleteAsync` already rotates API keys on failure, but it always uses the one model in `Ai:Gemini:Model` (default `gemini-3.8-flash`). `Ai:ModelCatalog` in `ProviderModelCatalog.cs` already lists `gemini-3.8-flash` and `gemini-3.8-pro` for Gemini, so the fallback list can be validated against it without new catalog entries. When every key returns QuotaExceeded, the document fails today instead of trying another model.

## Affected modules and files

- `src/Collector.Infrastructure/Ai/GeminiDirectProvider.cs` - model loop over the fallback list, exhausted-model tracking, per-model input check
- `src/Collector.Infrastructure/Ai/GeminiKeyRotation.cs` - reports all-keys-quota so the provider can move to the next model
- `src/Collector.Infrastructure/Ai/GeminiErrorMapper.cs` - keeps Transient, auth and other Permanent kinds off the fallback path
- `src/Collector.Infrastructure/Options/GeminiProviderOptions.cs` - adds `FallbackModels`
- `src/Collector.Infrastructure/Options/OptionsValidators.cs` - rejects unknown and duplicate fallback models
- `src/Collector.Infrastructure/Options/ProviderModelCatalog.cs` - source list the validator checks against
- `src/Collector.Presentation/appsettings.json` - ordered `Ai:Gemini:FallbackModels`, empty default
- `tests/Collector.Tests/Ai` - fallback, exhaustion, validator and empty-list tests

## Assumptions

- A model that returns QuotaExceeded for all its keys is skipped for the rest of the run. No cooldown timer.
- An empty `FallbackModels` list keeps today's single-model behavior.
- Logs carry the model id only. Keys never appear in logs.

- `AiFailureKind.QuotaExceeded` is raised only after the last configured model is exhausted

## Open questions

- Per-model `MaxInputTokens`: the brief says limits can differ by model. Confirm whether the limit becomes a per-model value or stays one shared setting.
