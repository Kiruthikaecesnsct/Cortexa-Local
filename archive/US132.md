# US132: Collector server rollback and resume

## Prerequisites / scope

- **Row-store delete folded in (pre-flight READY - fold)**: IPipelineRowStore needs per-container, batch-scoped delete before reverse-order rollback can run. Added to the "Reverse-order rollback" task, covering the port and the Cosmos adapter in desktop/collector/server. Same layer, under 4h, no new public contract. A missing row (404) counts as already deleted. No separate task; still 8.0h / 1.0 pt.
- **Depends on US123**. Blocks US133.
- **No pipeline retry for collector documents**: re-upload is the recovery path. Web Retry stalls until the watchdog fails the batch.
- **Scope lock**: all code stays inside desktop/collector. Nothing in services/, contracts/, frontend/ or deploy/ is edited or referenced.

## Planning notes

- Parallel UpsertAllAsync means a failed write may still have landed. Rollback must delete every planned deterministic id, not only the ids that reported success.
- Zero events published counts as "before publish", so rollback still applies.
- A 409 on replay needs an additive payload fingerprint stored on the saga row. Same Idempotency-Key with a different payload returns 409.

## Affected areas

- desktop/collector/server: row-store port, Cosmos adapter, saga row, batch handler.
