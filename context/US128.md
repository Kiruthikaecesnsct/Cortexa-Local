# US128: Show Batch Progress and Candidates in History

## Scope & Prerequisites

- **Backend prerequisite folded in from proposed US129 follow-up**: Server-side extension of batch and results endpoints now part of this story. Originally planned as a separate item; folded to keep History UI and its data contracts together.
- **Collector server stays independent**: Must run on `localhost:5091` separately from main preview stack.
- **No changes to services/ or frontend/**: All code lives inside `Cortexa-dev/desktop/collector/` (both server and UI).

## Contract Extensions (Backend)

Two endpoints extended via this story's backend tasks:

### GET /collector/batches
- **Previous return**: batch list with batch_id, batch_name, created_at, raw saga state (only InProgress shown)
- **New return**: adds `stage` field (Ingested|Extracted|Scored|Harvested|Seeded) and counts for harvesting/seeding completion
- **Owner-scoping**: Returns 404 for batches belonging to other users (determined by collector server session)

### GET /collector/batches/{id}/results
- **Previous return**: list of knowledge links only (BatchResultDto: engine, knowledge_item {id, kind, title, summary}, source)
- **New return**: flat candidates[] array where each candidate carries:
  - `candidate_id`, `engine`, `title`, `kind`, `evidence_count`, `score`, `patentability`
  - `knowledge_links[]` (original knowledge item + source) nested inside each candidate
- **Evidence/score/patentability source**: Read from Cosmos `evidence_bundles`, `verdicts`, and `reports` tables via new CosmosPipelineRowStore queries
- **Owner-scoping**: Returns 404 for batches owned by other users

## Affected Modules

**Backend (desktop/collector/server)**:
- `CosmosPipelineRowStore`: Add methods to query verdicts, evidence_bundles, and reports by batch_id and candidate_id
- Batch result endpoint: Transform flat knowledge links + verdicts + evidence into candidates[] structure
- Batch list endpoint: Extract and return saga stage enum + harvesting/seeding counts

**Client (desktop/collector/ui)**:
- History screen: Poll GET /batches for list view; show stage and progress
- Batch detail: Fetch GET /batches/{id}/results; render candidate cards with evidence_count, score, patentability
- Source navigation: Join server batch/document IDs to local file paths via SqliteBatchStore query; enable file open on click

## Integration Points

- **US127**: Provides the initial batch polling API (GET /collector/batches); this story extends that contract
- **US126**: Prerequisite for extraction/upload; batch records created there are read by this story's polling and results endpoints
- **Local SqliteBatchStore**: Must be kept in sync with server batch writes (US126 responsibility); US128 reads it for file path resolution

## Open Questions / Notes

- **SqliteBatchStore schema**: Confirm that document_id + source type (PDF vs code) + file_path are stored. If schema is incomplete, update it before US128 implementation starts.
- **Cosmos schema for verdicts/evidence**: Evidence count is the count of rows in evidence_bundles for a candidate. Patentability is the latest verdict score. Confirm schema assumptions with Cosmos schema docs before implementation.
- **Stage enum mapping**: Saga state machine is Ingested → Extracted → Scored → Harvested → Seeded. Confirm this sequence and any terminal/error states from job-orchestrator's saga definition.
